# Каталог — фаза 2

## Готово

- Главное меню сохраняет inline-поиск и настройки, добавлена кнопка каталога.
- Разделы: все сериалы, категории/жанры, новинки, тренды, популярное,
  рекомендации администратора и избранное. Пустые разделы и страницы за
  пределами диапазона обрабатываются корректно.
- Новинки сортируются по published_at, затем ID. Популярное — по уникальным
  подтверждениям; тренды — по ним же за период 1–365 дней (по умолчанию 7).
  При равенстве используется ID для стабильного порядка.
- Карточки показывают постер, название, жанры, количество серий, статус,
  описание и число подтверждений. Ошибка постера приводит к текстовой карточке.
  Текст экранируется и ограничен с учётом UTF-16 для Telegram captions.
- Кнопки: смотреть, избранное, самостоятельное подтверждение просмотра, назад.
  Для эпизодов есть отдельное меню с пагинацией. Подтверждение двухэтапное;
  повторная доставка и конкурентные запросы не увеличивают счётчик.
- Inline сохраняет текстовый поиск, опечатки и ImgBB, ищет альтернативные
  названия, поддерживает offset-пагинацию по 50 результатов и скрывает hidden.
- В /admin сохранены прежние функции. Добавлены категории, их название/порядок,
  удаление с подтверждением и период трендов. В редакторе сериала доступны все
  дополнительные поля с валидацией, preview, подтверждением и отменой.
- У каждого нового обработчика есть проверка прав; пользовательские callbacks
  повторно проверяют подписку, капчу и ban. Старые кнопки скрытого/удалённого
  сериала не изменяют избранное или просмотры.
- Все новые пользовательские и административные тексты есть в RU/UK/EN.

## Как управлять

Открыть `/admin` → редактирование сериала → нужное поле. Текущие значения и
формат ввода показаны в форме. Название, TikTok и постер используют прежние
сценарии. Описание — до 500 символов, альтернативные названия — через запятую,
категории — ID из показанного списка. Знак `-` очищает необязательные списки
или описание. Эпизоды: одна строка `название | https://...` на эпизод.

Статус выпуска: `ongoing`, `completed`, `announced`. Публикация: `published`
или `hidden`. Рекомендация: `1`/`0`. Дата — ISO 8601 с часовым поясом;
сохраняется в UTC. `updated_at` обновляется автоматически. При публикации
скрытого сериала published_at становится текущим, если дата не задана явно.

Категории создаются и редактируются как `название | порядок`, например
`Комедия | 10`. Порядок сортируется по возрастанию, затем по ID. Удаление
категории сохраняет сами сериалы.

## Данные и совместимость

`series.json` остаётся единственным каталогом. Поля: id, title,
alternative_titles, photo_url/photo_file_id, description, episode_count,
release_status, category_ids, tiktok_url, episodes, published_at, updated_at,
publication_status, recommended. Неизвестные поля записей и верхнего уровня
сохраняются. `next_id` монотонный: удалённый ID больше не выдаётся.

SQLite дополняется таблицами categories, favorites, confirmed_views,
catalog_settings и индексами просмотров. Для пользователя/сериала действует
уникальное ограничение подтверждения и избранного. Ссылки на series_id
проверяются CatalogService по JSON, а не по второму каталогу в SQLite.

В users добавляется delivery_blocked. Новые ошибки доставки рассылки отмечают
этот флаг, а не is_blocked. Новое обращение пользователя через ensure_user
сбрасывает delivery_blocked; административный ban сохраняется. Старые
is_blocked не изменяются автоматически: происхождение значения неоднозначно.

Баллы пока не начисляются; рейтинги и отзывы — фаза 3, ledger — фаза 4.
Кнопки и раздел топа для этих функций появятся после их реализации.

## Безопасное обновление Railway

Production в этой работе не менялся. Перед выкладкой остановить старый polling,
снять SQLite backup и скопировать весь текущий DATA_DIR. Проверить обновление
на копии. При запуске приложение:

1. Подготавливает отсутствующие JSON в DATA_DIR без замены существующих.
2. Для старого JSON создаёт `series.json.pre-v2.<UTC>.bak`, добавляет schema
   version 2, next_id и значения новых полей. ID и постеры сохраняются.
   Старые сериалы опубликованы; неизвестные старые даты получают стабильное
   значение `1970-01-01T00:00:00+00:00`, которое можно изменить в админке.
3. Перед ALTER users сохраняет SQLite backup рядом с базой, добавляет
   delivery_blocked, создаёт новые таблицы/индексы без очистки данных.

Повторный запуск идемпотентен. Неизвестная версия JSON отклоняется без записи;
повреждённые записи сохраняются в резервной копии и не заменяются пустыми.
Исходные резервные копии хранить отдельно от Volume для отката. При смене
DATA_DIR старую пользовательскую базу нужно перенести заранее: автоматического
импорта SQLite из другой файловой системы нет. Явные DB_PATH/LOGS_DIR должны
указывать на Volume. Команда остаётся `python main.py`, веб-сервер не нужен.
