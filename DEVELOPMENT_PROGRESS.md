## Что исправлено

- Общая проверка живого членства в `services/access_service.py`. Включённая
  проверка с пустым каналом запрещает доступ. Ограниченный участник допускается
  только при `is_member=True`; ошибки Telegram API запрещают доступ.
- Inline не читает каталог для заблокированных, не прошедших капчу и
  неподписанных пользователей. Отказы не содержат сериалов; кнопка ведёт
  в личный чат через `start_parameter`. Ответы персональные, `cache_time=0`.
- Middleware блокирует обработку обновлений заблокированных пользователей,
  включая старые callback и административные обработчики.
- `show_welcome` проверяет язык, капчу и блокировку. Старая кнопка проверки
  подписки больше не позволяет открыть главное меню до капчи.
- Капча, запущенная из сообщения бота, использует ID владельца личного чата,
  а не ID отправителя сообщения — бота.
- LocaleMiddleware извлекает пользователя из вложенного Update, сохраняя сам
  Update для диспетчера и восстанавливая ContextVar после обработки.
- Каталог, состояние очистки сообщений и логи учитывают DATA_DIR.
- Перед загрузкой handlers новый Volume получает исходные JSON без замены
  существующих файлов. Существующие файлы, включая повреждённые, не затираются.
- Локальный запуск сохраняет старую `database/users.db`, если DATA_DIR не задан.
- Перед добавлением language/subscription-колонок создаётся SQLite backup.
- Git игнорирует рабочие базы и резервные копии.

## Railway и безопасная миграция

Сохранены `python main.py`, long polling и прежние переменные окружения.
Для Volume: `DATA_DIR=/data`, целевая база `/data/users.db`. Явные DB_PATH и
LOGS_DIR переопределяют значения по умолчанию: при их наличии проверить,
что они также указывают внутрь Volume.

Перед сменой DATA_DIR остановить старый экземпляр и сохранить **фактическую**
производственную базу через SQLite backup API, а также series.json,
settings.json, captcha_answers.json и .message_cleanup.json. Проверить
PRAGMA integrity_check и количество users на копии. Перенести копии в Volume
до запуска новой версии. Иначе новый пустой Volume создаст новую базу:
автоматического переноса базы из старой файловой системы нет.

Проверить миграцию на копии, сопоставить пользователей/капчу/admin-флаги и
каталог до и после. Хранить внешнюю копию исходных файлов для отката. Не
копировать только users.db из работающего WAL-процесса обычным файловым copy.
Не запускать два polling-экземпляра. Для обязательной подписки установить
SUBSCRIPTION_REQUIRED=true, ID канала и ссылку; назначить бота администратором.
Включение без ID теперь корректно запрещает выдачу сериалов.
