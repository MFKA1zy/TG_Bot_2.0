# Фаза 5 — ежедневная рулетка

Дата: 2026-10-24. База: `3d599cd`, ветка `feature/daily-roulette`.
Production Railway и рабочая база не изменялись. Push не выполнялся.

## Реализовано

- Бесплатное вращение через главное меню и профиль; баланс общий с фазой 4.
  RU/UK/EN, результат, отдельное сообщение о нулевом призе, точный таймер,
  история с пагинацией по 8 записей.
- Призы по умолчанию: 0/20%, 5/30%, 10/25%, 20/15%, 50/8%, 100/2%.
  Выбор `secrets.randbelow(100)`, целочисленные веса; генератор подменяется
  только через конструктор для тестов. Telegram-анимация не определяет приз.
- Админка: полный список призов, изменение баллов/весов, добавление,
  отключение, мягкое удаление, переключение рулетки, интервал 1–720 часов,
  статистика и распределение с пагинацией, история пользователя по Telegram ID.
  Ввод проходит FSM и подтверждение, привязанное к сообщению. Версия настроек
  защищает от устаревшего подтверждения; права повторно проверяются в транзакции.
- Исторический размер выигрыша хранится отдельно от изменяемого приза.
  Изменение интервала действует на будущие попытки, сохраняя прежние дедлайны.
- Статистика рулетки в профиле; награды входят в прежний журнал и лидерборд.
  Записи `roulette_reward`, включая нулевой приз, используют `EconomyRepository._post`.

## Атомарность и ограничение времени

`BEGIN IMMEDIATE` сериализует конкурирующие записи. Внутри одной транзакции:
проверка пользователя → поиск ключа callback → проверка включения и последнего
дедлайна → выбор приза → общий ledger и баланс → история вращения → commit.
Ошибка любого шага откатывает все изменения, включая использование попытки.

По умолчанию `next_available_at = spun_at UTC + 86400 секунд`, без привязки
к полуночи или пользовательскому часовому поясу. Ровно на границе разрешено
новое вращение. Оставшееся время округляется вверх до секунды.

Ключ `callback:<callback.id>` уникален. Повтор возвращает исходную запись даже
через несколько суток и после новых вращений; баланс в ответе текущий.
Чужой ключ отклоняется. Новый callback в течение cooldown не создаёт запись.
SQLite busy/locked: до 3 попыток с timeout 250 мс и асинхронными паузами
20/40 мс; после исчерпания пользователь получает сообщение о занятости.

Используются существующие проверки капчи, языка, блокировки и живой подписки.
Callback подтверждается до проверки подписки и операций SQLite. Персональное
право вращения не кэшируется. Конфигурация читается один раз внутри нового
вращения, без риска устаревшего кэша после административного изменения.

Лёгкая анимация — одно редактирование и `asyncio.sleep(0.15)` после commit,
затем результат. Ошибка анимации не отменяет начисление; при недоступности
редактирования результата выполняется отправка нового сообщения. Даже если
Telegram совсем недоступен, сохранённый результат можно прочитать в истории
или повторной доставкой того же callback без второго начисления.

## SQLite и Railway

Миграция 5: `roulette_settings`, `roulette_prizes`, `roulette_spins`.
Внешние ключи связывают пользователя, приз и уникальную операцию ledger;
`request_key` уникален. Индексы `roulette_user_history(user_id,id DESC)` и
`roulette_prize_history(prize_id,awarded_points)`.

Старый CHECK в `points_ledger` не разрешал `roulette_reward`. SQLite не умеет
расширять CHECK через ALTER COLUMN: выполнено транзакционное пересоздание
физической схемы ledger с тем же итоговым именем, всеми строками, ID,
AUTOINCREMENT sequence, индексами и триггерами. Остальные таблицы фаз 1–4
не пересоздаются. До миграции существующей базы создаётся резервная копия
через SQLite backup API; после — `foreign_key_check`. Маркер 5 делает повторный
запуск идемпотентным. Проверено сохранение старых начислений и следующего ID.

Новых зависимостей и переменных окружения нет. Сохраняются Python 3.12,
`python main.py`, polling, SQLite WAL, `DATA_DIR=/data`, DB_PATH и Railway Volume.
Startup smoke test на временном Volume входит в полный pytest. Живой Railway
и сетевой Telegram не запускались. Перед публикацией нужен обычный smoke test
в тестовом боте и миграция копии фактической production-базы.

подделку callback, профиль/лидерборд, пагинацию, подтверждения админки,
миграцию/backup/индексы/целостность и сбой Telegram API после commit.
RU/UK/EN проверены общими тестами ключей и форматирования локалей.

Компиляция Python и `git diff --check` успешны. Проверка шаблонов секретов
в tracked/new файлах не выявила совпадений; `.env` не включён. Логический
dump рабочей SQLite совпадает с исходной локальной резервной копией.
