# Фаза 3 — оценки, отзывы, модерация и производительность

Дата: 2026-10-24. База разработки: `37938b9`, ветка
`feature/ratings-reviews-moderation`. Production Railway не изменялся,
push не выполнялся. Существующая локальная база не мигрировалась для разработки:
проверки и benchmark использовали временные базы и каталоги.

## Функциональность

- Оценки 1–10, изменение собственной оценки, среднее и количество голосов.
  Пара user/series уникальна, SQL CHECK ограничивает значение. Повторный
  callback не создаёт голос; повторная доставка старого callback не отменяет
  более позднюю оценку. Удаление оценки администрацией немедленно меняет агрегат.
- Рейтинг встроен в карточку и список каталога. Раздел «Топ по оценкам»
  использует настраиваемый минимум голосов (3 по умолчанию), среднее,
  количество голосов и ID для стабильного разрешения равенств.
- Один текстовый отзыв 10–1000 символов на пользователя/сериал. Создание,
  чтение, собственный отзыв, редактирование и soft-delete работают через FSM.
  Редактирование увеличивает версию и снимает непроверенный текст с публикации.
  Устаревшая административная кнопка не одобряет изменённый текст.
- В публичном списке есть имя автора, его оценка, дата и текст; Telegram ID
  не выводится. Одна полная запись на страницу позволяет не обрезать отзыв
  с 1000 emoji по лимиту Telegram. HTML экранируется.
- По умолчанию все отзывы pending. Можно включить публикацию безопасных;
  подозрительные остаются pending. Явно запрещённые можно направлять на проверку
  или отклонять. Состояния: pending/published/rejected/deleted.
- Отдельный фильтр выполняет NFKC/casefold, удаляет zero-width, учитывает
  простые leetspeak/смешанные алфавиты, разнесённые буквы и маски символами.
  Используются границы слов, правила ссылок, рекламы и повторяющегося текста.
  Это локальная эвристика, а не семантическая модель; ручная проверка остаётся
  режимом по умолчанию. Причины видны только администрации.
- Редактируемый словарь хранится в SQLite. Изменения отдельных выражений
  атомарны и не теряются при одновременной работе двух администраторов.
- Интервал отправки отзывов — 30 секунд по умолчанию, изменяемый в админке.
  Ограничение хранится в базе и действует между разными сериалами и рестартами.
  Одинаковая доставка сообщения идемпотентна даже при конкурентных запросах.
- Жалобы с четырьмя причинами, запретом жаловаться на себя и уникальностью
  user/review. Есть административная очередь, отклонение жалобы и разрешение
  жалоб после скрытия/отклонения отзыва. Количество жалоб не блокирует автора.
- /admin → «Управление отзывами»: очереди всех статусов, жалобы, поиск текста
  с Unicode casefold, настройки, словарь, статистика, поиск пользователя по ID.
  В деталях доступны автор, сериал, одобрение/отклонение/удаление и удаление
  оценки автора. Действия требуют причины и подтверждения, проверяют роль
  в handler и в транзакции; их журнал сохраняется в SQLite.
- Пользовательская модерация: предупреждения, снятие, постоянный ban/unban,
  причина/дата/администратор, история с пагинацией. Блокировка использует
  прежний `users.is_blocked`; user_bans хранит историю и метаданные, а не второй
  независимый признак доступа. Настраиваемая автоблокировка по предупреждениям
  по умолчанию выключена. Конфигурированные ADMIN_IDS и собственный аккаунт
  защищены от предупреждения/блокировки этим интерфейсом.
- Предупреждения сохраняются в журнале и доступны администрации; отдельная
  рассылка уведомлений пользователям не запускается. Временные баны не добавлены:
  поддержаны постоянные блокировки и явная разблокировка.
- Капча, язык, живая подписка и блокировка проверяются перед защищёнными
  callbacks и текстом FSM. Автор берётся из from_user, а не из callback_data.
  Общий middleware продолжает запрещать все действия заблокированным.
- Все новые сообщения и кнопки есть в RU/UK/EN. Баллы не начисляются.

## Оптимизации

- JSON-каталог кэшируется по fingerprint файла: mtime_ns, ctime_ns, size, inode.
  Запись немедленно инвалидирует кэш; другие экземпляры сервиса и внешние
  изменения обнаруживаются по fingerprint. Ошибка/повреждение не заменяется
  старой кэшированной выдачей. Публичные данные возвращаются копиями.
- Кэш результатов поиска ограничен 128 запросами и связан с конкретным
  snapshot. Скрытие/удаление через админку немедленно исключает сериал.
- Поиск одного ID копирует одну запись вместо всего каталога. Дисковые
  операции каталога, приветствий, капчи и сохранения состояния сообщений
  вынесены из asyncio в `asyncio.to_thread`. Сетевые операции остаются async.
- Состояние карточки получено одним SQL SELECT: избранное, просмотр,
  количество просмотров, среднее/число/собственная оценка. Вместе с категориями
  это два запроса вместо пяти в прежней подготовке карточки; полные пользовательские
  списки и общая статистика каталога для одной карточки больше не загружаются.
- Для обычной страницы рейтинги загружаются одним запросом только для её ID.
  Публичные отзывы читаются одним JOIN с users/ratings, без запросов на автора.
  Добавлены индексы рейтингов, очередей, публичных отзывов, жалоб и журнала.
- Снимок пользователя переиспользуется только в рамках текущего Update:
  LocaleMiddleware, ban middleware и guard не делают одинаковый SELECT трижды.
  Между Update проверки доступа не кэшируются. Записи рейтингов/отзывов также
  проверяют текущий ban внутри транзакции.
- Callback каталога и отзывов подтверждается до проверки подписки и работы
  хранилища. Отказы не открывают защищённый контент.
- Одновременные одинаковые getChatMember объединяются только пока запрос
  выполняется. Следующее действие снова обращается к API; положительного TTL
  нет. Отмена одного ожидающего не отменяет проверку остальных.
- Постеры сначала отправляются по Telegram file_id. Если он недействителен,
  используется ImgBB URL, затем текстовый fallback. Полученный file_id хранится
  в ограниченном памяти кэше по bot/image. Смена постера меняет ключ.

## Измерения

Одинаковый `tools/benchmark_bot.py` запущен на копии коммита 37938b9 и новой
версии: Windows, Python из `.venv312`, 1000 синтетических сериалов, временная
SQLite, 40 повторов (callback — 20). Таблица — медианы, миллисекунды.

| Операция | До | После |
| --- | ---: | ---: |
| Чтение списка каталога | 28.381 | 13.330 |
| Повторный точный inline-поиск | 33.760 | 0.594 |
| Хранилище + подготовка карточки | 55.093 | 15.055 |
| Страница новинок | 31.568 | 20.076 |
| Отдельный view_counts SQLite | 8.111 | 9.171 |
| Полный callback с API stub | 63.037 | 46.718 |
| Время до подтверждения callback с API stub | 21.339 | 0.923 |

Это фактические локальные wall-clock замеры, **не измерения production или сети
Telegram**. В callback проверка подписки имела синтетическую задержку 10 мс.
У 16 одновременных проверок подписки число API-вызовов уменьшилось с 16 до 1;
их wall-clock время 14.953 → 24.939 мс не показывает ускорения сети. Отдельный
неизменённый view_counts также не ускорился: вариации нагрузки Windows заметны.
Снижение числа обращений и ранний ack подтверждены тестами, вне зависимости
от этих временных колебаний. Реальная задержка Telegram/ImgBB не измерялась.

Исходные JSON с median/p95:
[до](benchmarks/phase3-before.json), [после](benchmarks/phase3-after.json).
Повторить текущую версию: `python tools/benchmark_bot.py --output result.json`.
Benchmark не обращается к настоящему Telegram и не изменяет рабочую базу.

## Миграция и Railway

Сохраняются Python 3.12, aiogram 3, polling, `python main.py`, DATA_DIR/DB_PATH,
каталог JSON и постеры ImgBB. При отсутствии BOT_TOKEN запуск прекращается
до изменения данных. SQLite дополняется tables ratings, rating_requests,
reviews, review_reports, review_moderation_events, user_warnings, user_bans,
review_settings, moderation_words, review_submission_limits, review_submissions
и schema_migrations (version=3).

Перед первым расширением существующей базы создаётся SQLite backup рядом
с ней. Создание таблиц/индексов идемпотентно. Первичная установка словаря и
маркер версии фиксируются вместе; удалённые администрацией слова не
возвращаются при рестарте. Рабочие connections включают foreign_keys=ON;
связи с пользователями, отзывами и отчётами имеют FK. Ссылки на series_id
проверяются по единственному JSON-каталогу в сервисе, поскольку второго
каталога в SQLite нет. Изменяющие операции используют BEGIN IMMEDIATE,
параметры, уникальные ограничения и UTC.

Перед production остановить прежний polling, сделать внешнюю резервную
копию SQLite через backup API и копию DATA_DIR, проверить эту версию на копии.
Проверить integrity_check, foreign_key_check, количество пользователей,
существующие серии, ID, постеры, просмотры и избранное до/после. Backup рядом
с базой не заменяет внешнюю копию. DATA_DIR=/data и явные пути должны находиться
на Volume. В этой работе production и реальная пользовательская база
не обновлялись; live проверка Telegram/ImgBB остаётся перед выкладкой.
