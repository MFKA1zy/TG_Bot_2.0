# План изолированного тестирования

Дата: 2026-10-24. Живой Telegram и Railway в фазе 6 не запускались.
Все результаты pytest относятся к локальным временным данным и API-заглушкам.

## Локальная тестовая копия

1. Создать **другого** бота через BotFather; включить `/setinline` для него.
   Production-токен не переносить. Создать отдельный тестовый канал, назначить
   тестового бота администратором: getChatMember других участников требует прав.
2. Скопировать `.env.test.example` в `.env.test` локально. Файл игнорируется Git.
   Вписать тестовый BOT_TOKEN, ID и ссылку тестового канала вручную. Не отправлять
   секреты в чат, issue, Git или скриншоты. `DATA_DIR=.staging-data`; DB_PATH и
   LOGS_DIR оставить пустыми: launcher задаст изолированные абсолютные пути.
3. Для первоначального администратора задать собственный ADMIN_IDS, отдельный
   ADMIN_ACTIVATION_CODE и временно ADMIN_CODE_ACTIVATION_ENABLED=true.
   После регистрации вызвать `/activate_admin`, ввести код. После проверки
   выключить активацию и перезапустить; флаг is_admin остаётся в тестовой SQLite.
4. Проверить из корня проекта без сети и записи данных:

   ```powershell
   .\.venv312\Scripts\python.exe tools/run_staging.py --env-file .env.test --check
   ```

5. Убедиться, что этот тестовый токен нигде ещё не используется для polling.
   Затем владелец может запустить тот же launcher без `--check`.
   Production-процесс с production-токеном продолжает работать отдельно.
6. Launcher отказывается от production `.env`, совпадающего известного токена,
   путей DATA_DIR внутри/над production-каталогом и перенаправления DB_PATH.
   Унаследованные секреты приложения удаляются; `ENV_FILE` исключает fallback
   к `.env`. Это защита от известных локальных путей, а не способ определить
   произвольные неизвестные production-секреты: правильный выбор токена остаётся
   обязанностью владельца. Обходить launcher для первого запуска не следует.

Не копировать рабочую базу пользователей в активного тестового бота. Иначе
административная рассылка сможет обратиться к реальным пользователям. Для
миграционных экспериментов использовать `migration_preflight.py`: он не
запускает polling. Для активного staging — синтетические пользователи или
пустая база. Встроенный стартовый JSON содержит каталог, но не аккаунты.

## Матрица живой проверки

Владелец заполняет дату, версию, устройство и результат для RU, UK, EN:

| Путь | Ожидаемый результат | Live статус |
|---|---|---|
| /start → язык → неверная/верная капча | Нет доступа до верной капчи | Не выполнено |
| Нет подписки → вступление → проверка | Появляется главное меню | Не выполнено |
| Категория → карточка → эпизоды → TikTok | Постер/HTML/ссылки корректны на телефоне | Не выполнено |
| Подтверждение просмотра дважды | Единственная награда +10 | Не выполнено |
| Оценка 8 → 9 | Один голос, обновлённая оценка | Не выполнено |
| Отзыв → очередь → approve/reject/delete | Публикация только по политике | Не выполнено |
| Жалоба дважды; фильтр/спам | Нет дубля жалобы, действует cooldown | Не выполнено |
| Профиль → истории → лидерборд | Баланс равен журналу | Не выполнено |
| Рулетка → double click → история | Один результат, таймер 24 часа | Не выполнено |
| Отписка → старые кнопки и inline | Доступ немедленно закрыт | Не выполнено |
| Ban → inline/отзыв/рулетка; unban | Запрет всех действий, затем восстановление | Не выполнено |
| Inline: exact/alias/typo/empty/missing/pages | Текст, постеры, TikTok, offset без дублей | Не выполнено |
| Рестарт → профиль и история | Начисления и таймер сохраняются | Не выполнено |

В админке проверить создание/редактирование/скрытие/удаление с подтверждением,
категории/эпизоды/рекомендации, ImgBB с верным и неверным тестовым ключом,
приветствия всех языков, поиск пользователя, warning/ban/unban, журнал,
баллы credit/debit, награду просмотра, призы/веса/выключение рулетки.
Рассылку проверять только на пустой/синтетической тестовой SQLite с аккаунтом
владельца; отмену и перезапуск проверить до запуска production-рассылок.
Смену политики подписки сейчас выполнять через env/Variables и рестарт:
редактора канала/исключений в Telegram-админке нет.

## Linux / Railway staging

Только после локальной проверки создать отдельный сервис/проект с отдельным
Volume, новым BOT_TOKEN и тестовым каналом. Не клонировать Variables целиком,
не подключать production Volume. Пустой DATA_DIR=/data; DB_PATH=/data/users.db.
Остановить локальную тестовую копию перед Railway polling тем же тестовым токеном.
Проверить Linux SIGTERM, права Volume, сохранность после redeploy, отсутствие
Conflict getUpdates, ошибок миграции, секретов и повторных наград в логах.
Dashboard/Volume/живой SIGTERM требуют действий владельца.

Критерий допуска к production: все строки live-матрицы заполнены, preflight
фактической копии production прошёл, backup проверен и сохранён вне Volume,
владелец явно одобрил выпуск. Локальный pytest сам по себе не даёт этот допуск.
